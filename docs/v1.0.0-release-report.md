# X-Pilot v1.0.0 Release Report

## Conclusion

X-Pilot v1.0.0 establishes the first stable reliability boundary for automation and Workspace-scoped views. The release preserves Schema v4 and `chrome.storage.local` while adding explicit UI scope semantics, deterministic Workspace cache reconciliation, stale-response protection, and START lease renewal.

## Implemented changes

The Side Panel now treats Workspace state as the canonical source for cross-view data. Mutation responses containing a complete Workspace state can be reconciled immediately, which prevents Queue, Tweet Banks, Sessions, and History from showing an earlier snapshot until the user changes Workspace.

Workspace filters now have explicit `ACTIVE`, `ALL`, and `SPECIFIC` modes. The default is the active Workspace. The `ALL` mode excludes archived Workspaces from operational views, while a specific Workspace remains pinned when the active Workspace changes. Clearing filters returns the view to the active Workspace.

The persisted START lock can now be renewed during long-running Preflight and startup work. The Service Worker renews the lease every five seconds and stops the heartbeat in `finally`, preserving cleanup on success and failure.

Alarm failure handling now accepts failures after the session has transitioned to `RUNNING`. A retry converts that ambiguous runtime state into an explicit `WAITING` state with a future trigger. Exhausted retries transition to `FAILED` and release the automation owner.

## Known limitation

The browser-level START harness and full X adapter simulation remain candidates for the next reliability increment. The production flow already records Publish Intent and uses conservative restart recovery, but a browser API simulator should be added before introducing further automation behavior.
